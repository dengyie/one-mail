# Unified Inbox Attachment Downloads

## Goal and contract

Persist attachment bytes for native Email Routing and aggregated IMAP/POP3/Graph mail, then expose an authenticated download action in the unified inbox.

Attachment metadata remains in `emails.attachments_json` and gains an opaque `id` plus a private `storage_key`. Clients address downloads by email ID and attachment ID; they never supply an object key. Object keys are generated by the Worker from tenant, email, and attachment identity. The private `ATTACHMENT_STORAGE_URL / ATTACHMENT_STORAGE_TOKEN` VPS storage binding is colocated with the owning D1 database (primary or shard).
