# 初始化/更新 D1 数据库

## 创建数据库

打开 cloudflare 控制台，选择 `Storage & Databases` -> `D1 SQL Database` -> `Create Database`，点击创建数据库

![d1](/ui_install/d1.png)

创建完成后，我们在 cloudflare 的控制台可以看到 D1 数据库

## 初始化数据库

::: warning 注意
你也可以跳过初始化数据库，在部署完成后，在 admin 页面的 `快速设置` -> `数据库` 中，点击 `初始化数据库` 按钮来初始化数据库
:::

打开 `Console` 标签页，输入仓库中 [db/schema.sql](https://github.com/dengyie/one-mail/blob/main/db/schema.sql) 文件的内容，点击 `Execute` 执行

![d1](/ui_install/d1-exec.png)

## 更新数据库 schema

管理员页面通过 `GET /admin/db_version` 检查状态，两个 `need_*` 字段始终是布尔值：

| 数据库状态 | `need_initialization` | `need_migration` | 下一步 |
| --- | --- | --- | --- |
| 尚无应用表 | `true` | `false` | 初始化 |
| 已有应用表，但缺少版本记录或版本不一致 | `false` | `true` | 执行结构迁移 |
| 版本为当前代码要求的版本 | `false` | `false` | 无需版本迁移 |
| D1 读取失败 | HTTP 错误，不返回状态对象 | 同左 | 重试状态检查 |

缺少 `db_version` 不代表空库。不要手写当前版本号跳过迁移：`POST /admin/db_migration` 会按实际表结构补齐缺项，全部成功后才更新版本记录。列依赖的索引在补列之后创建，重复执行保留已有邮件。初始化和迁移在前置状态读取失败时不会执行 DDL；状态接口只做有界元数据/版本读取，不代替完整结构迁移校验。

页面在操作期间禁用按钮，并在重新读取到当前版本后确认成功。操作或后续读取失败时，使用「重新检查状态」只重试 GET，不自动重复提交迁移。离开页面会取消客户端请求；已经提交到服务器的迁移仍需重新读取状态确认结果。

`schema` 更新，请确认你之前部署的版本,

查看 [更新日志](https://github.com/dengyie/one-mail/blob/main/CHANGELOG.md)

找到需要执行的 `patch` 文件, 执行, 例如:  `db/2024-01-13-patch.sql`

打开 `Console` 标签页，输入 `patch` 文件的内容，点击 `Execute` 执行
