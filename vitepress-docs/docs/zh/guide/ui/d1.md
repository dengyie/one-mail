# 初始化/更新 D1 数据库

## 创建数据库

打开 cloudflare 控制台，选择 `Storage & Databases` -> `D1 SQL Database` -> `Create Database`，点击创建数据库

![d1](/ui_install/d1.png)

创建完成后，我们在 cloudflare 的控制台可以看到 D1 数据库

## 初始化数据库

::: warning 注意
你也可以跳过初始化数据库，在部署完成后，在 admin 页面的 `快速设置` -> `数据库` 中，点击 `初始化数据库` 按钮来初始化数据库
:::

打开 `Console` 标签页，输入仓库中 [db/schema.sql](https://github.com/dengyie/one-mail/blob/main/db/schema.sql) 文件的内容，点击 `Execute` 执行

![d1](/ui_install/d1-exec.png)

## 更新数据库 schema

管理员页面通过 `GET /admin/db_version` 检查状态，两个 `need_*` 字段始终是布尔值：

| 数据库状态 | `need_initialization` | `need_migration` | 下一步 |
| --- | --- | --- | --- |
| 尚无应用表 | `true` | `false` | 初始化 |
| 已有应用表，但缺少版本记录或版本不一致 | `false` | `true` | 执行结构迁移 |
| 版本为当前代码要求的版本 | `false` | `false` | 无需版本迁移 |
| D1 读取失败 | HTTP 错误，不返回状态对象 | 同左 | 重试状态检查 |

缺少 `db_version` 不代表空库。不要手写当前版本号跳过迁移：`POST /admin/db_migration` 会按实际表结构补齐缺项，全部成功后才更新版本记录。列依赖的索引在补列之后创建，重复执行保留已有邮件。初始化和迁移在前置状态读取失败时不会执行 DDL；状态接口只做有界元数据/版本读取，不代替完整结构迁移校验。

迁移合并表结构查询并批量执行修复，为免费档单次 D1 调用上限留出余量；批处理不会减少扫描行数或索引写入计费。结构迁移是低频管理操作，不应作为定时状态检查重复执行。

主库管理接口还会在 DDL 前检查缺失的邮件索引，以 `70,000 - 当日已观测 rows_written` 作为维护写预算；有界抽样按每条邮件、每个索引估算，包含对 partial index 的保守高估。超过预算返回 **409 `D1_MIGRATION_WRITE_BUDGET`**，附 `pending_indexes`、`index_write_estimate`、`estimate_capped`、`available_write_rows` 和 `quota_confidence`。达到抽样上限时估算不是全表精确成本。应结合 Cloudflare 账户真实用量，将缺失索引分批安排到有预算的维护窗口，再重试迁移；不要重复点初始化或手写版本号。该检查仅覆盖主库管理初始化/迁移中的邮件索引构建，不覆盖全部回填、其他表、分片初始化、CLI 或 CI 直接 SQL，不能当作账户硬余额或全迁移预算保证。

页面在操作期间禁用按钮，并在重新读取到当前版本后确认成功。操作或后续读取失败时，使用「重新检查状态」只重试 GET，不自动重复提交迁移。离开页面会取消客户端请求；已经提交到服务器的迁移仍需重新读取状态确认结果。

## 每日配额耗尽与恢复

Cloudflare 明确报告免费 D1 每日读或写额度耗尽时，Worker API 返回 **503**，响应体包含 `code`（`D1_DAILY_READ_LIMIT` 或 `D1_DAILY_WRITE_LIMIT`）及 ISO-8601 UTC 的 `retry_at`；`Retry-After` 是距下一个 UTC 零点的向上取整秒数，响应禁止缓存。其他 5xx 不使用这套暂停语义，应用的局部用量估计也不会触发 ingest 熔断。

聚合器收到明确配额响应后停止当前目标的批内重试，其他健康目标继续上传；对应账号的暂停截止时间保存到现有 `SyncState`，IDLE、Graph 和轮询在重启后仍遵守该时间，到期按调度恢复。文件夹和状态回写遭遇同类故障也会暂停账号；失败批次不会推进水位。普通网络故障仍走既有有限重试。mutation/outbound 队列保留各自 60→120→240→300 秒退避，不宣称所有后台请求都暂停到零点。

若在额度耗尽期间部署，先记录明确的 UTC 重置时间及受影响账号，停稳聚合器后备份状态，再写入对应账号的暂停截止时间并启动新版本。不要在进程运行时从另一个进程改写状态文件，也不要为了验证反复兑换 OAuth refresh_token。部署不能恢复已耗尽的额度；验收必须在额度重置后确认真实非空入库，读接口 200 和进程 RUNNING 不足以证明收信恢复。
